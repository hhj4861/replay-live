# 도우미 연결 코드 자동 입력 — 2026-09-20

## 변경 동작

로그인한 웹의 영상 링크 화면을 열거나 새로고침·재로그인하면 PC 도우미의 현재 연결 코드를 입력란에 채운다. `코드 불러오기` 버튼으로 재조회할 수도 있다. 자동 조회 자체는 세션을 만들지 않으며, `내 컴퓨터 연결` 버튼으로 실제 페어링한다.

조회 실패는 입력란 바로 아래 `role=alert`로 표시한다. 최신 도우미 실행, 브라우저 로컬 연결 권한 허용, 재조회 또는 수동 입력을 안내한다. 사용자가 직접 입력하거나 화면을 떠나면 진행 중 조회를 취소하여 늦은 응답이 값을 덮어쓰지 않는다. 계정 변경 응답도 폐기한다.

## 경계와 호환성

- `GET http://127.0.0.1:17833/pairing-code`는 기존 middleware의 정확한 Host·허용 Origin·`X-Replay-Local: 1` 검사를 통과한 웹에만 현재 코드를 제공한다. 응답은 `no-store`다.
- 이 변경으로 허용된 웹 출처는 수동 코드 전달 없이 코드를 읽을 수 있다. Origin 허용 목록은 신뢰 경계이므로 신뢰하지 않는 출처를 추가하면 안 된다. 세션 토큰 요구와 작업별 소유권 검사는 그대로 유지한다.
- 코드는 PC 도우미 프로세스 수명에 종속된다. 로그인별 고정 코드가 아니다. 클라우드 API·브라우저 저장소·문서·로그에는 코드를 복사하지 않는다. 기존 CLI의 실행 창 출력은 유지한다.
- 기존 도우미는 새 조회 경로에 404를 반환한다. UI는 업데이트/수동 입력 안내를 제공한다. 웹과 각 PC 도우미를 모두 갱신해야 자동 입력이 동작한다.
- 자동 연결이나 동영상 가져오기 시작은 하지 않는다. 클라우드 저장소 업로드 502 수정은 이번 범위에 포함하지 않는다.

- Python: `tests/test_local_import_daemon.py tests/test_device_imports.py` **46 passed**. 코드 최신값, 미인증 조회 후 세션 미생성, no-store, 악성·누락 Origin/Host/header 거절, PNA preflight 및 기존 작업 격리를 확인했다.
- 클라이언트: `npm run test:client` **198 passed**. 자동 조회/버튼 조회, 응답 형식, 구버전·미실행 오류, 수동 편집·unmount·계정 변경 후 늦은 응답 폐기, 재마운트/연결 해제 후 조회를 포함한다.
- `npm run lint`, `tsc --noEmit`, `REPLAY_COMMERCIAL=1 npm run build:vercel`, `git diff --check` 통과.
- 실제 Chrome에서 로컬 검증 화면(127.0.0.1:3100)의 실제 React 연결 컴포넌트와 실제 PC 도우미 API(127.0.0.1:17833)를 사용했다. 최초 자동 입력 → 실제 페어링 성공, 새로고침 후 자동 입력, 값을 지운 뒤 버튼/키보드로 다시 불러오기, 로그아웃/로그인에 대응하는 컴포넌트 제거·재마운트 후 자동 입력을 확인했다.
- 도우미를 종료하고 Chrome을 새로고침하여 화면 오류와 연결 버튼 비활성화를 확인했다. 도우미 재시작 후 `코드 불러오기`로 오류가 해제되고 새 코드로 실제 페어링에 성공했다.
- 브라우저의 로그인 전환은 로컬 검증 화면의 재마운트 시험이다. 이번 변경으로 운영 Google 재로그인이나 운영 업로드 완료를 검증했다고 주장하지 않는다.
