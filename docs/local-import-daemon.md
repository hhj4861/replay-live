# 사용자 PC에서 영상 가져오기 — 2026-09-19

각 사용자가 자기 PC의 도우미를 연결한다. 클라우드가 사용자별 작업을 만들고 PC 데몬이 원본을 내려받아 클라우드 저장소로 직접 업로드한다.

```text
웹 링크 입력 → 클라우드 작업 생성 → 웹이 작업 ID·임시 권한을 PC에 전달
PC → 클라우드에서 해당 작업 조회 → 원본 다운로드 → 저장소 직접 업로드
PC → 클라우드 완료 확인 → 영상 검사 → 웹 보관함에서 재생
```

클라우드는 PC의 포트에 직접 접속하지 않는다. 열린 웹이 작업만 전달하고 데몬이 클라우드에 요청하므로 공유기 포트 개방이 필요 없다. 영상 파일은 브라우저를 경유하지 않는다. 로그인 토큰·Google 인증 정보·스트림 키·저장소 관리자 자격도 데몬에 보내지 않는다.

## 현재 실행 방법

각 PC에 프로젝트 Python 의존성(`requirements.lock`), FFmpeg와 ffprobe가 필요하다. 프로젝트 폴더에서 다음을 실행하고 웹의 **영상 링크**를 연다. 브라우저의 해당 사이트 로컬 연결 권한을 허용하면 **도우미 연결 코드**가 자동 입력된다. **내 컴퓨터 연결**을 누른 다음 영상을 가져온다. 비어 있다면 **코드 불러오기**를 누르거나 실행 창의 코드를 직접 입력한다.

```bash
.venv/bin/python scripts/local-import-daemon.py
```

기본 API는 `https://replay-live-api.vercel.app`이다. 다른 배포는 `--cloud-url https://정확한-API-도메인`으로 지정한다. 웹 요청으로 API 주소를 바꿀 수 없다. 다른 웹 출처는 `--origin`으로 지정한다. 이전 도우미는 새 웹에서 업데이트 안내를 받는다.

## 현재 권한과 제한

- 클라우드 작업은 조직과 사용자 ID에 함께 묶인다. 데몬 권한은 한 작업의 조회·업로드·완료·실패 보고에만 한정된다. 임시 권한은 최대 10분이며 원래 로그인 만료를 넘지 않는다. Google 세션의 로그아웃·갱신·관리자 차단도 재확인한다.
- 원본 링크는 DB에 암호화하고 임시 권한은 해시만 저장한다. 완료·취소·실패 때 원본을 지우고, 만료 작업은 정기 maintenance와 같은 사용자의 다음 요청에서 정리한다. 백업 복원 시 기존 작업 권한을 폐기한다.
- 데몬은 `127.0.0.1:17833`에서만 듣는다. 정확한 Host·Origin·전용 헤더로 코드 조회를 제한한다. 허용된 웹은 페어링 전 현재 코드를 읽을 수 있으며, 연결 버튼으로 세션을 발급한 후 세션별로 작업을 격리한다.
- 사용자별 클라우드 작업 하나, PC별 동시 다운로드 하나다. 영상은 최대 50MiB·120초이며 서버 한도와 사용자 남은 용량이 더 작으면 그 값을 적용한다. 원본 다운로드 제한은 120초, 웹 전체 대기는 9분이다.
- 웹 취소 버튼은 다운로드·업로드 중단과 미완료 업로드 정리를 요청한다. 이미 완료 확인에 들어간 영상은 검사 후 보관함에서 확인한다. 로그아웃·계정 변경 시 기존 PC 연결을 해제한다.
- 업로드 성공·실패 후 PC 임시 파일을 삭제한다. 정상 종료도 임시 폴더를 삭제한다. 강제 종료·전원 차단 때는 OS 임시 파일이 남을 수 있다.
- 보관함 등록까지 웹과 데몬을 켜둔다. 브라우저 종료 뒤 재개는 지원하지 않는다. 요청 전달 중 연결이 끊기면 기존 작업 만료까지 최대 10분 동안 새 요청이 제한될 수 있다.
- 로컬에서도 원본 플랫폼이 접근을 제한할 수 있다. 쿠키 추출·프록시·플랫폼 로그인·봇 확인 우회 기능은 없다. 실패해도 클라우드 원본 다운로드로 전환하지 않는다.
- 터미널 실행 방식이며 OS 자동 시작과 서명된 설치 프로그램은 제공하지 않는다.

## 운영 적용과 검증 상태

운영 적용에는 `migrations/010_device_imports.sql` → API → 웹 배포와 각 PC의 도우미 업데이트가 필요하다. 새 운영 API의 기존 `/api/media/imports` 경로는 서버 다운로드 대신 도우미 업데이트 안내를 반환한다.

**현재 수정본은 로컬에만 적용했다. 운영 DB 마이그레이션·API·웹 배포는 아직 실행하지 않았다.**

- 합성 MP4로 실제 Chrome 창을 열어 PC 연결 → 작업 전달 → 데몬 직접 업로드 → FFmpeg 검사 → 보관함 재생과 기존 송출 회귀 흐름을 확인했다.
- 사용자 링크 `https://youtu.be/GcOe4ILS6Ow?si=MwRd2upBrYaxK7lN`도 실제 Mac 다운로드와 같은 브라우저 흐름을 통과했다. 영상은 1,194,527바이트, 17.024초, 360×640, H.264/AAC다.
- 실제 링크 검증에서 브라우저 영상 업로드 0건, 데몬 파일 읽기 0건, 서버 원본 다운로드 0건, JavaScript 오류 0건이었다. 서버에는 영상 검사 작업만 생성됐다.
- 최종 재실행에서는 영상의 실제 재생 시간이 1.34초까지 진행되고 일시정지 상태가 아님을 확인했다. 증거: `/tmp/replay-device-import-real-browser-final-20260919.json`과 같은 이름의 `.png`. 합성 E2E: `/tmp/replay-device-import-browser-fixed-20260919.json`.
- 웹 테스트 184개, TypeScript와 린트 통과. 서버 전체 최초 실행은 939개 통과·24개 환경별 생략·AWS 테스트 구성 오류 3개였다. SQLite를 사용하는 AWS 테스트 구성만 수정한 뒤 해당 테스트·새 작업 테스트·마이그레이션 도구 테스트를 재실행해 28개 통과·PostgreSQL 통합 1개 생략을 확인했다.
- 임시 로컬 API·SQLite·파일 저장소와 합성 OIDC를 사용했다. 실제 운영 Google 로그인·Vercel 저장소·외부 방송 송출 성공을 의미하지 않는다.

```bash
REPLAY_E2E_HEADED=1 .venv/bin/python scripts/commercial-browser-smoke.py \
  --device-import --source-url 'https://youtu.be/GcOe4ILS6Ow?si=MwRd2upBrYaxK7lN' \
```

# 이전 구현 기록 — 2026-09-15 (현재 방식으로 대체됨)

아래는 브라우저가 파일을 전달하던 이전 구현의 기록이다. 현재 실행·배포 절차는 위 내용을 따른다.

스튜디오의 **영상 링크 → 영상 가져오기**는 이제 이 컴퓨터의 데몬을 호출한다. 데몬이 녹화 영상을 MP4로 내려받으면 웹이 파일을 수신하고 SHA-256을 확인한 뒤 현재 로그인한 회원의 기존 업로드 경로로 보관함에 등록한다.

```text
웹의 링크 입력 → 127.0.0.1:17833 도우미 → 원본 플랫폼 다운로드
             ← MP4 수신·해시 검증
웹 → 로그인한 회원의 /api/uploads → 저장소 업로드 → /complete → 영상 검사 → 보관함
```

웹 로그인 토큰, Google 인증 정보, 스트림 키, 클라우드 저장소 자격 증명은 데몬에 전달하지 않는다. 데몬은 클라우드 API나 DB에 접근하지 않는다. 웹은 기존 회원·저장 용량·무결성·영상 검증 정책을 그대로 거친다. 새 DB 마이그레이션이나 클라우드 API 배포가 필요하지 않다. 새 웹 빌드를 배포해야 운영 웹에서도 이 흐름이 적용된다.

## 실행

기존 프로젝트의 Python 환경과 FFmpeg를 사용한다. Python 의존성은 `requirements.lock`에 고정되어 있다. 새 컴퓨터는 프로젝트 README의 Python 환경 설치를 먼저 진행한다. FFmpeg와 ffprobe가 PATH에 있어야 한다.

```bash
cd /Users/admin/workSpace/replay-live-poc
.venv/bin/python scripts/local-import-daemon.py
```

1. 웹 스튜디오의 **영상 링크**를 열면 이 PC에서 실행 중인 최신 도우미의 **연결 코드**를 자동으로 읽는다. **코드 불러오기**로 다시 조회할 수도 있다.
2. 코드가 입력되면 **내 컴퓨터 연결**을 누른다. 이전 도우미나 연결 권한 문제로 조회가 실패하면 화면 안내를 확인하거나 실행 창의 코드를 직접 입력한다.
3. 브라우저가 로컬 컴퓨터 연결 권한을 요청하면 허용한다.
4. 원본 플랫폼과 영상 링크를 입력하고 **영상 가져오기**를 누른다.
5. 다운로드 → 웹 전달 → 보관함 업로드 → 영상 검사 후 새 영상이 자동 선택된다.

이번 작업의 별도 미리보기는 `http://127.0.0.1:13104/`다. 이 주소를 허용하려면 다음처럼 실행한다.

```bash
.venv/bin/python scripts/local-import-daemon.py --origin http://127.0.0.1:13104
```

기본 허용 웹 출처는 `https://replay-live-poc.vercel.app`, `http://127.0.0.1:13101`, `http://127.0.0.1:3100`, `http://localhost:3100`이다. 별도 웹 도메인은 `--origin https://정확한-웹-도메인`으로 지정한다. 경로·와일드카드·임의 HTTP 주소는 사용할 수 없다.

연결은 열린 웹 화면에서 유지된다. 새로고침·새 탭·재로그인에서는 현재 코드를 자동으로 읽은 뒤 **내 컴퓨터 연결**을 다시 누른다. 코드는 브라우저 저장소에 보관하지 않는다. 로그아웃이나 계정 변경 시 기존 연결과 진행 작업을 해제한다. 연결 코드는 로그인 사용자별 고정값이 아니며, 각 PC의 데몬을 재시작할 때 바뀐다. 지금은 터미널에서 실행하는 개발용 도우미이며 OS 자동 시작·서명된 데스크톱 설치 프로그램은 제공하지 않는다.

## 종료·취소 및 보관

- 가져오기를 중단하려면 웹의 **가져오기 취소**를 누른다. 다운로드와 진행 중인 업로드를 중단하고 완료되지 않은 업로드 기록 정리를 시도한다.
- 도우미를 종료하려면 실행 터미널에서 `Ctrl+C`를 누른다.
- 보관함 업로드까지 웹 화면과 도우미를 켜두어야 한다. 서버에 보관이 끝난 영상은 이후 도우미 없이 사용할 수 있다.
- 데몬 파일은 웹이 수신한 뒤 삭제한다. 실패·취소 파일도 정리한다. 웹 연결 단절 등으로 남은 임시 작업은 실행 중인 데몬이 최대 30분 뒤 정리한다. 정상 종료 시 자신의 임시 폴더를 삭제한다. 강제 종료·전원 차단 시 OS 임시 디렉터리에 파일이 남을 수 있다.
- 클라우드 업로드가 실패하면 원본 링크로 다시 시도한다. 브라우저를 닫은 뒤의 다운로드·업로드 재개는 지원하지 않는다.

## 경계와 제한

- 서버 바인딩은 `127.0.0.1`에 고정, 포트는 17833. 외부 인터페이스·공유기 포트 개방은 필요하지 않다.
- Host·정확한 Origin·전용 요청 헤더를 검증한다. 브라우저 연결 권한/PNA 요청을 처리하며 쿠키 인증은 사용하지 않는다.
- 연결 코드는 무작위 48비트, 연결 시도는 분당 5회. 연결 세션 토큰은 무작위 256비트이며 서버 메모리에 해시로 보관하고 웹 메모리에만 유지한다. 세션은 최대 8시간, 최대 8개다.
- 작업·파일은 연결 세션별로 격리한다. 별도 탭·계정의 연결로 다른 작업을 읽거나 취소할 수 없다.
- 한 번에 다운로드 작업 1개, 임시 작업 최대 8개, 완료 파일과 신규 예약 용량 합계 200MiB 이내. 다운로드 입력·변환 중간 파일에는 기존 다운로드 모듈의 별도 경계가 적용된다.
- 영상당 최대 50MiB·120초, 실제 다운로드 최대 120초. 서버 한도·회원의 남은 공간이 더 작으면 작은 값을 사용한다. 웹은 다운로드·수신 단계를 180초로 제한한다.
- HTTPS 원본만 허용하며 사설 IP, 내부 주소, 비정상 리다이렉트 등을 차단하는 기존 DNS 고정 전송 경로를 사용한다.
- 쿠키 추출, 프록시, 플랫폼 로그인 또는 봇 확인 우회 기능은 추가하지 않았다. 로컬에서도 원본 플랫폼이 접근을 제한하면 실패 코드와 안내를 표시한다.
- 새 웹에서는 기존 서버 `/api/media/imports`를 호출하거나 실패 시 그 경로로 재시도하지 않는다. 기존 API는 이전 클라이언트와의 호환성을 위해 유지되어 있다.

HTTPS 웹에서 로컬 도우미에 연결할 때는 브라우저의 로컬 네트워크/루프백 권한이 적용될 수 있다. 브라우저 보안 기능을 끄지 말고 해당 사이트의 연결 권한을 사용한다. [MDN 로컬 네트워크 접근](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Local_network_access), [MDN 루프백의 보안 컨텍스트](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Mixed_content)
