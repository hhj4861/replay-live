# 브랜치와 통합 순서

사용자 지시(2026-09-19): 기능 브랜치를 새로 만들어 작업하며 통합은 **`feat/*` → `develop` → `main`** 순서로 진행한다.

- `feat/*`: 구현·검증·커밋·정상 push를 수행하는 작업 브랜치.
- `develop`: 기능 PR의 대상. 통합 검증 후 `main`으로 PR을 만든다.
- `main`: 릴리스 기준 브랜치. 기능 브랜치에서 바로 통합하지 않는다.
- PR 생성까지 진행할 수 있으나, 각 PR의 실제 merge는 사용자의 명시적 승인을 받은 뒤 수행한다. 자동 merge나 기준 브랜치 직접 push로 승인 절차를 대신하지 않는다.
- force push, 다른 세션의 staged 작업 포함, 훅·인증 우회는 하지 않는다.

## 최초 기준과 현재 작업

기존 저장소에는 `master`의 최초 POC 커밋 `f64532b`만 있었다. 새 `main`과 `develop`은 이 커밋에서 시작하며 기존 `master`는 보존한다. 새 기능 코드는 `feat/per-user-device-import`에만 커밋한다. 기준 브랜치를 생성하는 것은 기능을 merge하는 것이 아니다.

사용자 승인에 따라 기존 미등록 상용 코드 중 PC 데몬 기능을 실행·검증하는 데 필요한 API·웹·DB 마이그레이션·설정 예시·테스트·실행 도구를 이번 기능 브랜치의 기준 코드로 함께 등록한다. 기존 README 수정, 과거 배포 증거·조사 기록, GCP 실험 도구와 로컬 에이전트 설정은 이 커밋 범위에 포함하지 않는다.

첫 PR은 `feat/per-user-device-import` → `develop`이다. 승인·통합·검증 뒤 두 번째 PR을 `develop` → `main`으로 준비한다. 로컬 커밋, 원격 push, PR merge와 운영 배포는 각각 별도 상태로 보고한다.
